# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Connection setup (`line 22`) | `MongoClient` initialized without `tz_aware=True`. Returns offset-naive datetimes from MongoDB, causing comparison errors or silent timezone mismatches against UTC datetimes. | Interacting with BSON datetimes raises `TypeError: can't compare offset-naive and offset-aware datetimes`. | Added `tz_aware=True` to `MongoClient(MONGO_URI, tz_aware=True)` and normalized timestamps with explicit UTC timezone. |
| 2 | Startup (`lines 22-29`) | No database indexes created at application startup (seeded database only has default `_id` index). | All queries perform full collection scans (`COLLSCAN`); duplicate `emp_code` or `(emp_code, date)` can be inserted concurrently. | Added an `@asynccontextmanager lifespan` hook creating compound and unique indexes on `employees` and `attendance_logs` idempotently. |
| 3 | `health` (`lines 72-74`) | Unconditionally returns `{"status": "ok"}` with HTTP 200 without checking if MongoDB is reachable. | Shut down MongoDB or supply an invalid `MONGO_URI`; `GET /health` still returns 200 instead of 503. | Added `client.admin.command("ping")` inside a `try/except` block, raising `HTTPException(503, "MongoDB unavailable")` on connection failure. |
| 4 | `create_employee` (`lines 79-84`) | Check-then-insert concurrency race condition: checks `find_one` before `insert_one`. | Two concurrent `POST /employees` with the same `emp_code` both pass the check and insert duplicates. | Enforced database-level unique index on `emp_code` and caught `DuplicateKeyError` to return HTTP 409 Conflict. |
| 5 | `EmployeeIn` model (`lines 53-60`) | Missing input validation for `emp_code`, `email`, name/department lengths, and shift times. Does not validate `shift_start != shift_end`. | Sending `"emp_code": "bad_code"`, negative lengths, or invalid time formats returns 201 instead of 422. | Added strict Pydantic field validators with regex for `emp_code` (`^EMP\d{4,6}$`), email, length constraints, and explicit check that `shift_start != shift_end`. |
| 6 | `create_employee` (`lines 81-85`) | `created_at` generated via local `datetime.now()` with microseconds; raw datetime object returned instead of epoch milliseconds. | Returned `created_at` is an ISO string/datetime object instead of epoch milliseconds integer; contains microseconds. | Stored UTC datetime truncated to whole seconds (`microsecond=0`) and serialized response to integer epoch milliseconds via `int(dt.timestamp() * 1000)`. |
| 7 | `list_employees` pagination (`line 93`) | Pagination offset computed as `skip = page * page_size`. For page 1, skips 20 records immediately, missing the first page. | Querying `GET /employees?page=1&page_size=20` returns records 21-40 rather than 1-20. | Corrected offset formula to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` count (`line 94`) | `total` counts entire collection via `count_documents({})` regardless of the `department` filter. | Filtering `GET /employees?department=Engineering` returns total employee count of all departments. | Changed to `total = db.employees.count_documents(q)` to count only filtered documents. |
| 9 | `list_employees` ordering (`line 95`) | Query does not sort results by `emp_code` ascending as required by API contract. | Returned items appear in arbitrary MongoDB natural insertion order. | Added `.sort("emp_code", ASCENDING)` to the query cursor. |
| 10 | `punch_in` employee lookup (`lines 101-113`) | `db.employees.find_one(...)` is not checked for `None` before accessing `emp["shift_start"]`. | Punching in for a non-existent `emp_code` raises an unhandled 500 `KeyError` / `TypeError`. | Added explicit validation: `if not emp: raise HTTPException(404, detail="employee not found")`. |
| 11 | `punch_in` race condition (`lines 104-118`) | Check-then-insert pattern permits concurrent requests on the same day to bypass check and insert duplicate logs. | Firing two simultaneous punch-ins for the same employee and date creates duplicate attendance records. | Enforced compound unique index `[("emp_code", 1), ("date", 1)]` on `attendance_logs` and caught `DuplicateKeyError` to return HTTP 409. |
| 12 | `PunchInIn` validation (`lines 63-67`) | Status field accepts any arbitrary string; `punched_at` accepts invalid or out-of-range epoch millisecond numbers. | Sending `status="ABSENT"` or `"punched_at": 100` succeeds with 201 instead of 422. | Restricted status to `{"PRESENT", "WFH", "ON_DUTY"}` and validated `punched_at` integer range `[100_000_000_000, 4_102_444_800_000]`. |
| 13 | `compute_late_minutes` (R1 & R2) (`lines 33-38`) | 1. Replaces hour/min on UTC datetime using IST shift start without timezone conversion. 2. `int(seconds / 60) > 10` evaluates `09:40:01` as 10 min, failing `> 10` and returning 0 instead of 10. | Punch at `09:40:01` (shift 09:30) returns `late_minutes = 0` instead of 10. | Converted punch to IST; evaluated total seconds difference strictly `> 600` seconds; returned `diff // 60`. |
| 14 | `punch_in` attendance date & overnight shifts (`line 103`) | `ts.date().isoformat()` takes server local date; fails to handle overnight shifts (R1). | Overnight shift (22:00-06:00) punch-in at 05:30 assigns current calendar date rather than previous day. | Implemented `get_attendance_date()`: for overnight shifts where punch time < shift end, decrements attendance date by 1 day. |
| 15 | `compute_work_hours` (R4) (`lines 40-41`) | Uses Python's built-in `round()` (banker's rounding, round-half-to-even) instead of `ROUND_HALF_UP`. | Exact midpoints like `x.xx5` round down to even numbers instead of rounding half-up. | Implemented `round_half_up` using Python `decimal.Decimal` with `ROUND_HALF_UP`. |
| 16 | `compute_overtime` (R3) (`lines 44-47`) | Does not enforce 30-minute threshold; fails overnight shifts by computing shift end on the same calendar day. | Punch-out 15 minutes after shift returns 15 instead of 0; overnight shift overtime yields negative or wrong offsets. | Counted overtime only if `minutes >= 30`; for overnight shifts, shift end date is advanced to `date + 1 day`. |
| 17 | `list_attendance` memory explosion (`lines 144-147`) | Fetches entire collection into Python memory (`list(db.attendance_logs.find(q))`), sorting and slicing in Python. | Testing against 100,000 records causes high memory allocation, query timeouts, or OOM crashes. | Moved sorting and pagination into MongoDB: `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`. |
| 18 | `list_attendance` validation & formatting (`lines 125-150`) | Missing validation for `date_from > date_to`; leaks MongoDB internal `_id` / `id`; leaves datetimes unformatted. | `date_from="2026-07-10"&date_to="2026-07-01"` does not return 422; response exposes `id` string. | Added `date_from <= date_to` validation returning 422; formatted response to exclude `_id` and converted datetimes to epoch ms. |
| 19 | `punch_out` record selection (`lines 481-485`) | Query found newest record by punch-in date without checking whether `punch_in <= punched_at`. | If an employee had a punch-in for Day 1 and another for Day 2, punching out for Day 1 selected Day 2 and returned 422. | Added `punch_in: {"$ne": None, "$lte": ts}` to the database query filter while maintaining descending sorting. |
| 20 | Trend analytics rounding (`lines 1040-1077`) | Used MongoDB's `$round` operator, which implements banker's rounding (round-half-to-even) rather than the required `ROUND_HALF_UP`. | Values like `0.00015` or `0.00035` round to `0.0001` and `0.0003` instead of `0.0002` and `0.0004`. | Replaced `$round` with Decimal128 mathematical expression: `{"$divide": [{"$floor": {"$add": [{"$multiply": [{"$toDecimal": "$val"}, 10000]}, 0.5]}}, 10000]}`. |
| 21 | Trend empty-data fallback & window averages (`lines 1263-1283`) | A Python loop fallback was triggered when aggregation returned 0 rows, which also incorrectly assigned `moving_avg_7d = None` on weekends. | Departments with 0 attendance logs produced incorrect trend calculations and violated the pure MongoDB aggregation requirement. | Relied entirely on MongoDB's `$densify` with explicit bounds `[from_dt, to_dt_excl]`, which generates all dates purely in the database; `$setWindowFields` correctly calculates rolling averages over `[-6, "current"]` across weekends. |
| 22 | Explain endpoint validation parity (`lines 1301-1405`) | Explain endpoint failed to apply the same parameter validations as real endpoints (e.g. invalid months like `2026-13`, reversed dates, invalid status, malformed date strings). | Malformed explain requests caused unhandled 500 exceptions instead of standard 422 validation errors. | Standardized parameter validation across all 5 explain branches using `validate_date_str`, `parse_month`, and enum checks. |
| 23 | Trend date-range boundary (`lines 1247-1250`) | Validation rejected ranges only when `(to_d - from_d).days > 92`, allowing 93 inclusive calendar days. | Sending a 93-day inclusive range (e.g., 2026-01-01 to 2026-04-03) returned 200 instead of 422. | Updated condition to `(to_d - from_d).days + 1 > 92` (or `.days > 91`) to strictly enforce maximum 92 inclusive calendar days. |
| 24 | Attendance date filter validation (`lines 529-554`) | Compared `date_from` and `date_to` purely as strings without validating format or calendar validity. | Passing `date_from=2026-02-30` or `not-a-date` was passed directly to the database instead of returning 422. | Added `validate_date_str()` verifying regex `^\d{4}-\d{2}-\d{2}$` and strict Python calendar parsing (`date.fromisoformat`). |
| 25 | Department summary cross-collection pipeline (`lines 1153-1213`) | Headcount and statistics were split into two separate queries and merged in Python. | Violated requirement that department summary be a MongoDB aggregation across both collections; increased network roundtrips. | Consolidated into a single aggregation rooted in `employees` matching `joined_on <= last_day`, with `$lookup` into `attendance_logs` and `$reduce` array aggregation. |
| 26 | Department summary explain query (`lines 1363-1374`) | Explain reported only the attendance log query, omitting the employee headcount aggregation. | Query execution plan did not match the actual execution path of the endpoint. | Pointed the explain branch to the unified `employees` aggregation pipeline matching the consolidated endpoint. |

### Examined and Decided Was Not a Defect
1. **Pydantic v2 `model_dump()` usage**: Looked at `body.model_dump()` throughout endpoints; confirmed this is standard and recommended in Pydantic v2.
2. **`ReturnDocument.AFTER` in atomic updates**: Verified `find_one_and_update(..., return_document=ReturnDocument.AFTER)` is correct for returning the post-update document atomically without extra read roundtrips.
3. **Optimistic locking via `history` array length check**: Inspected `{"history": {"$size": hist_len}}` on regularization updates. Verified this correctly guarantees conflict detection under concurrent updates without table locking.
